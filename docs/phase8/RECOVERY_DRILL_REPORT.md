the drill and intentionally not logged alongside evidence contents. No benchmark
claim follows from one tiny restore or one synthetic input.

The restore utility accepts no caller-supplied destination DB: it constructs new
UUID names, checks emptiness before restore, and asserts the cf_restore_ identity
before cleanup. No pg_restore --clean or DROP FORCE. It refuses existing output
paths. A failed cleanup due to unknown clients must be investigated, never forced.
The function's cleanup confirms database removal only on successful completion;
incomplete result directories are not valid backups.

Neither restored backup authentication checks nor data hashes prove encrypted,
off-machine backup delivery, loss recovery, log ACL, operational RPO/RTO, full role
grant correctness or actual alert response. The synthetic restored users have no
usable credentials/sessions. Real restore must revoke resurrected sessions and
replay deletion obligations before traffic; this policy step is still operator-owned.
Deleting a live report does not erase old backups automatically. Keep a restricted
withdrawal/deletion ledger and approved backup-retention schedule.
